# TRANSLATOR.md — перевод речи RU → EN в VoicePaste

План для ИИ-агента (Claude Sonnet). Дополняет `AGENTS.md`: все правила оттуда (стек, правила кода, отчёты после этапа, «не забегай вперёд») действуют и здесь. Прочитай файл целиком, прежде чем писать код.

**Когда начинать:** после того как пользователь подтвердит этап 6 (окно настроек). Перевод делаем **до** этапа 7 из `AGENTS.md`; этап 7 потом учтёт перевод (README, чек-лист).

**Две версии приложения (решение пользователя).** Выпускаются две сборки: **обычная** (как сейчас, без перевода) и **с переводчиком**. Для этого весь код перевода (хоткеи перевода, `translate.rs`, `llm_server.rs`, группа в настройках, пункт в трее, ключи `[translate]` в конфиге, ветки в `stt.rs`) прячется за Cargo-фичей `translator`, **выключенной по умолчанию**:
- обычная сборка не содержит кода перевода, не показывает его в интерфейсе и не пишет ключи `[translate]` в `config.toml`;
- сборка с переводчиком: `--features translator` (вместе с `cuda`/`console` как обычно); `scripts\build-release.ps1` получает параметр `-Translator`, а `scripts\package.ps1` — суффикс `-translator` в имени пакета;
- в тестах и в `clippy` проверяются **обе** конфигурации (`cargo clippy --all-targets -- -D warnings` с фичей и без неё);
- пакет с переводчиком не включает модели и `llama-server.exe` (они скачиваются из настроек), но README к нему описывает требования.
Не делай перевод до того, как пользователь подтвердит готовность обычной версии (релиз 1.0).

## 1. Цель

Пользователь говорит по-русски, а в активное поле вставляется **английский** текст (и он же кладётся в буфер обмена). Всё бесплатно и локально: никаких платных API и облака. Сеть только для однократного скачивания моделей и программ по явной команде пользователя.

### Как пользователь включает перевод (решение пользователя: «и то и другое»)
1. **Отдельные горячие клавиши перевода.** К двум существующим добавляются ещё две, работают так же, но результат на английском:
   - `hotkey.translate_toggle` (по умолчанию `Ctrl+Alt+E`): нажал — запись, нажал ещё раз — стоп → английский текст;
   - `hotkey.translate_push_to_talk` (по умолчанию `""`, то есть выключена): держишь — запись, отпустил → английский.
2. **Галочка «Переводить всегда»** (`translate.always`) в меню трея и в окне настроек: когда включена, обычные клавиши тоже выдают английский.

Итог: перевод выполняется, если запись начата клавишей перевода **или** включена галочка. Решение принимается **в момент старта записи** и не меняется, даже если галочку переключили во время записи.

### Движок перевода (решение пользователя: «поэтапно»)
- **Шаг 1 — Whisper translate.** Встроенный режим Whisper «любой язык → английский». Почти без нового кода и зависимостей, качество среднее (бывает буквальным).
- **Шаг 2 — локальная LLM через llama.cpp.** Распознаём русский как обычно (turbo, лучшее качество распознавания), затем переводим текст небольшой языковой моделью. Качество заметно выше: естественный английский, сохраняются термины.
- Пользователь выбирает движок в настройках (`translate.engine = "whisper" | "llm"`).

## 2. Ключевые технические факты (проверь, прежде чем полагаться)

1. **Модель `large-v3-turbo` НЕ обучалась переводу.** OpenAI прямо пишет об этом для turbo: в режиме translate она часто просто выдаёт русский текст или переводит плохо. Для Whisper-перевода нужна модель, умеющая translate: `ggml-large-v3-q5_0.bin` (~1.1 ГБ) или `ggml-medium-q5_0.bin` (~0.5 ГБ). **Проверь на реальных записях пользователя (этап T0), а не по памяти.** Список файлов: `https://huggingface.co/ggerganov/whisper.cpp/tree/main`.
2. **Нельзя линковать llama.cpp в тот же exe, что и whisper.cpp.** `whisper-rs-sys` и `llama-cpp-sys-*` оба статически собирают свою копию `ggml` → дублирующиеся символы (`LNK2005`) и/или несовместимые версии ggml. Поэтому LLM запускается **отдельным процессом** `llama-server.exe` (официальный сервер llama.cpp, OpenAI-совместимый HTTP API на `127.0.0.1`). Плюсы: сбой или нехватка памяти у LLM не роняют VoicePaste, обновлять llama.cpp можно независимо.
3. **Не добавляй Ollama/LibreTranslate/Python** — это лишние внешние установки. `llama-server.exe` — один каталог с exe и DLL.
4. Версии крейтов, имена файлов релизов llama.cpp, доступность моделей на HuggingFace **проверяй в момент работы** (AGENTS.md, раздел 2). Сеть для этого используй только по согласованию с пользователем.
5. Особенность среды разработки (см. память проекта): записи агента в `%APPDATA%` пользователь не видит. Тестовые модели и exe клади в `C:\VoicePaste\models\` / `C:\VoicePaste\tools\` и передавай пути явно (`--model`, CLI-флаги), как делали раньше.

## 3. Конфигурация

Новые ключи (старые конфиги без них читаются, берутся значения по умолчанию; `config::render()` выводит их с комментариями):

```toml
[hotkey]
toggle = "Ctrl+Alt+D"
push_to_talk = "Ctrl+Alt+S"
translate_toggle = "Ctrl+Alt+E"       # press, speak Russian, press again -> English
translate_push_to_talk = ""           # hold, speak Russian, release -> English ("" = off)

[translate]
always = false                        # true = every recording is translated to English
engine = "whisper"                    # "whisper" | "llm"
on_error = "original"                 # "original" = paste the Russian text | "nothing"

# engine = "whisper"
whisper_model = "ggml-large-v3-q5_0.bin"   # must support translation; turbo does NOT
whisper_prompt = "Hello. This is a clean English translation with correct punctuation."

# engine = "llm"
llm_server = "llama/llama-server.exe"      # relative to %APPDATA%\VoicePaste, or absolute
llm_model = "qwen2.5-3b-instruct-q4_k_m.gguf"  # file in the models folder
llm_gpu_layers = 99                        # -ngl; 0 = CPU only
llm_preload = true                         # start the server with the app, not on first use
llm_timeout_seconds = 20
```

Валидация в `sanitized()`: `engine`/`on_error` — только допустимые значения, `llm_timeout_seconds` 3..120, `llm_gpu_layers` 0..999.
Хоткеи: все **четыре** сочетания проходят через `hotkey::resolve` — дубликаты между любыми двумя запрещены, пустая строка отключает.

## 4. Архитектура

### 4.1 Хоткеи и state machine (`hotkey.rs`, `app.rs`)
- В `hotkey.rs`: `Binding { trigger: Trigger, hotkey, text }`, где
  ```rust
  #[derive(Clone, Copy, PartialEq, Eq, Debug)]
  pub struct Trigger { pub mode: Mode, pub translate: bool }
  ```
  `resolve()` принимает четыре строки (лучше `&HotkeyCfg`) и возвращает до четырёх привязок. Подписи для ошибок: «переключатель», «удержание», «перевод: переключатель», «перевод: удержание».
- `PressFilter` — по одному на каждый `Trigger` (4 штуки, массив или `HashMap<Trigger, _>`).
- `State::Recording { started, trigger: Trigger, translate: bool }`. `translate` вычисляется в момент старта: `trigger.translate || cfg.translate.always`. Чтобы `transition` оставалась чистой, передай `always` через `Settings` (`Settings::translate_always`).
- `Event::HotkeyPressed(Trigger, Instant)` / `HotkeyReleased(Trigger, Instant)`. Правило остановки прежнее: остановить запись может только **тот же** `Trigger` (тот же режим и тот же признак перевода).
- `Effect::StopAndTranscribe { translate: bool }`.
- Все существующие тесты `transition` переписать под `Trigger` и добавить новые (раздел 7).

### 4.2 Конвейер в STT-потоке (`stt.rs`)
- `Job::Transcribe { audio: Captured, translate: bool }`.
- Новый `WorkerMsg::Stage(Stage::Translating)`, чтобы оверлей показал «ПЕРЕВОЖУ…».
- Результат: `WorkerMsg::Text(Result<Dictation, String>)`, где
  ```rust
  pub struct Dictation { pub text: String, pub translated: bool, pub fallback: bool }
  ```
  `fallback = true`, если перевод не удался и вернули русский оригинал (`on_error = "original"`).
- Порядок:
  1. resample → trim silence (как сейчас; пустая речь → пустой текст, без перевода);
  2. `translate == false` → как сейчас;
  3. `engine = whisper` → распознать **сразу в английский** моделью перевода (раздел 4.3);
  4. `engine = llm` → распознать по-русски turbo-моделью → `Stage(Translating)` → `Translator::translate(text)` (раздел 4.4).
- Постобработка (`postprocess::finalize`) применяется к итоговому тексту как сейчас, в главном потоке.

### 4.3 Whisper-перевод
- `SttEngine::transcribe(pcm)` → `transcribe(pcm, Task)`, где `enum Task { Transcribe, TranslateToEnglish }`. Для перевода: `params.set_translate(true)`, `language` = `"ru"` (или `auto`, если в конфиге auto), `initial_prompt` = `translate.whisper_prompt` (английский).
- **Второй контекст модели.** Если `translate.whisper_model != stt.model`, воркер держит второй `SttEngine` для перевода и загружает его **лениво** при первом переводе (или при старте, если `translate.always`). Если имена совпадают, используется тот же движок. Смена `whisper_model` в конфиге → `Job::Reconfigure` перезагружает только этот движок.
- Если файла модели перевода нет: ошибка «Нет модели перевода <имя>, скачайте её в настройках», дальше по `on_error`.

### 4.4 LLM-перевод (`translate.rs`, `llm_server.rs`)
**`llm_server.rs` — управление процессом `llama-server.exe`:**
- Запуск: `llama-server -m <gguf> --host 127.0.0.1 --port <port> -ngl <n> -c 2048 --no-webui` (имена флагов сверь с `llama-server --help` конкретной версии). Порт — свободный, найденный через `TcpListener::bind("127.0.0.1:0")`. **Только 127.0.0.1**, никогда 0.0.0.0.
- Флаг процесса `CREATE_NO_WINDOW` (`std::os::windows::process::CommandExt::creation_flags(0x0800_0000)`), stdout/stderr → `logs\llama-server.log`.
- **Job Object** с `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`: если VoicePaste упадёт, сервер тоже завершится и не останется висеть в памяти видеокарты. WinAPI-код держи в `llm_server.rs` с комментариями `// SAFETY:`.
- Готовность: опрос `GET /health` раз в 250 мс до 200 OK, таймаут 60 с (модель грузится несколько секунд).
- Падение сервера → лог + одна автоматическая попытка перезапуска при следующем запросе; повторное падение → ошибка в трее.
- Остановка при выходе из приложения и при смене `llm_model`/`llm_server`/`llm_gpu_layers` (перезапуск с новыми параметрами).
- `llm_preload = true` → старт вместе с приложением, если перевод вообще возможен (есть хоть одна клавиша перевода или `always`); иначе ленивый старт при первом переводе.

**`translate.rs` — HTTP-клиент и чистые функции:**
- Запрос `POST /v1/chat/completions` через `ureq` (уже в стеке; для JSON добавь `serde_json` — обоснуй в отчёте), `stream: false`, `temperature: 0.1`, `max_tokens` ≈ `3 × (символов в тексте / 2) + 64`, таймаут `llm_timeout_seconds`.
- Системный промпт (английский, константа):
  ```
  You are a translation engine. Translate the user's message from Russian to natural, fluent English.
  Rules: output ONLY the translation — no quotes, no notes, no explanations, no preface.
  Keep the meaning, tone and register; do not add or remove information.
  Keep names, brands, code, file names, commands, URLs and numbers as they are.
  If parts of the message are already in English, keep them.
  If the message is already entirely in English, return it unchanged.
  ```
  Текст пользователя передаётся как `user`-сообщение **без изменений** (это данные, а не инструкции; системный промпт важнее).
- `fn build_request(text, cfg) -> serde_json::Value` и `fn clean_reply(reply: &str) -> Option<String>` — **чистые функции с тестами**. `clean_reply`:
  - убирает обрамляющие кавычки `"…"`, `«…»`, `'…'`, блоки ```` ``` ````;
  - убирает типовые преамбулы: `Translation:`, `Here is the translation:`, `Sure, here…:`, `English:`;
  - отрезает хвосты вида `\n\nNote:` / `(Note: …)`;
  - схлопывает пробелы; пустой результат → `None`.
- Проверка результата: если в ответе больше 30 % кириллицы, перевод считается неудачным (дальше по `on_error`).

### 4.5 UI
- **Оверлей:** запись с переводом — «ЗАПИСЬ → EN 0:05»; этап перевода — «ПЕРЕВОЖУ…» (зелёный, как «РАСПОЗНАЮ…»).
- **Трей:** `CheckMenuItem` «Переводить на английский» ↔ `translate.always`. Клик пишет конфиг через `config::save_atomic` (watcher применит). В подсказке трея при включённой галочке — «→ EN».
- **Окно настроек:** новая группа «Перевод на английский» в том же ретро-стиле:
  - галочка «Переводить всегда»;
  - две строки хоткеев (переключатель перевода и удержание перевода) — переиспользуй `hotkey_row`;
  - движок: «Whisper (встроенный)» / «Локальная языковая модель (llama.cpp)»;
  - для Whisper: выбор модели перевода из папки моделей + подсказка «turbo не умеет переводить»;
  - для LLM: статус «llama-server найден / не найден», выбор `.gguf` из папки моделей, кнопка «Проверить перевод» (переводит «Привет! Как дела? Открой файл config в VS Code.» и показывает результат и время);
  - поведение при ошибке: «Вставить русский оригинал» / «Ничего не вставлять».
- **Звуки:** перевод не удался и вставлен оригинал → звук `Error` после вставки; в логе `warn`.

### 4.6 Скачивание
Кнопки «Скачать» делаются в рамках этапа 7 вместе со скачиванием Whisper-моделей (`model_download.rs`, `.part` + rename). До этого:

Распаковать в одну папку. Если готовая сборка не запустится на этой машине, допустим запасной вариант: собрать `llama-server` из исходников (CMake + CUDA уже установлены) — **спроси пользователя перед этим**.
- Любое скачивание — только с разрешения пользователя (размер и источник называть заранее).

### T0. Замеры, решения по моделям (без UI)

- Расширь `--transcribe-file`: флаг `--task translate`.
- Скачай (с разрешения) `ggml-large-v3-q5_0.bin` и `ggml-medium-q5_0.bin` в `C:\VoicePaste\models\`.
- Сравни на записях пользователя: turbo-translate, large-v3-translate, medium-translate — время и качество. Покажи пользователю таблицу и рекомендуй модель по умолчанию.
- **Критерий:** подтверждено (или опровергнуто) на реальных записях, что turbo не годится для перевода; выбрана модель для Whisper-перевода.

### T1. Хоткеи перевода, галочка, Whisper-движок
- Конфиг (`[translate]`, новые хоткеи), `hotkey::resolve` на 4 привязки, `Trigger` в state machine, `Job::Transcribe { translate }`, `Task::TranslateToEnglish`, ленивый второй движок.
- Трей: `CheckMenuItem` «Переводить на английский».
- Оверлей: «ЗАПИСЬ → EN».
- **Критерий:** в Блокноте `Ctrl+Alt+E` → русская фраза → `Ctrl+Alt+E` → английский текст; обычные клавиши дают русский; галочка в трее переводит всё; переключение галочки во время записи не меняет текущую запись.

### T2. Сервер llama.cpp и консольная проверка LLM
- `llm_server.rs` (запуск, health, Job Object, логи, остановка), `translate.rs` (запрос, промпт, `clean_reply`).
- CLI: `voicepaste --translate-text "Привет, как дела?" [--model <gguf>] [--server <exe>]` печатает перевод и время (сервер стартует и останавливается сам).
- Выбор LLM-модели: кандидаты для сравнения на 10–15 фразах пользователя (тексты из T0): `Qwen2.5-3B-Instruct Q4_K_M` (лицензия Apache-2.0), `Gemma-3-4B-it Q4_K_M`, при наличии — более новые небольшие мультиязычные instruct-модели. **Проверь актуальные модели и их лицензии на HuggingFace в момент работы**, не по памяти. Покажи пользователю примеры переводов и время, пусть выберет.
- **Критерий:** `--translate-text` выдаёт естественный английский за < 1.5 с на типичную фразу (после загрузки модели); после завершения процесса `llama-server` не остаётся в диспетчере задач (проверь и при аварийном завершении VoicePaste).

### T3. LLM-движок в приложении
- Подключить `engine = "llm"`: распознавание turbo → `Stage(Translating)` → перевод; `llm_preload`; перезапуск сервера при смене настроек; `on_error`; проверка доли кириллицы.
- Оверлей «ПЕРЕВОЖУ…», звук ошибки при откате на оригинал.
- **Критерий:** диктовка с переводом через LLM работает обеими клавишами перевода и галочкой; если убить `llama-server.exe` вручную, следующая диктовка перезапускает его (или, если не вышло, вставляет русский оригинал со звуком ошибки), приложение не падает.

### T4. Окно настроек: группа «Перевод на английский»

## 7. Тесты

- `hotkey::resolve`: 4 привязки; дубликат между обычной клавишей и клавишей перевода → ошибка; пустые строки отключают.
- `transition`:
  - клавиша перевода стартует запись с `translate = true`, обычная — с `false`;
  - при `translate_always = true` обычная клавиша даёт `translate = true`;
  - запись, начатая клавишей перевода, не останавливается обычной клавишей того же режима, и наоборот;
  - `StopAndTranscribe { translate }` несёт признак, вычисленный при старте (смена `translate_always` во время записи его не меняет).
- `config`: новые ключи по умолчанию, round-trip `render`/`parse`, старый конфиг без `[translate]`, ограничения значений.
- `translate::clean_reply`: кавычки, `«»`, преамбулы, `Note:`, code fences, пустой ответ; `build_request`: текст пользователя передаётся как есть.
- Доля кириллицы: чистая функция `cyrillic_ratio(&str) -> f32`.
- `llm_server`: чистая функция сборки аргументов командной строки; запуск реального сервера — тест с `#[ignore]` (запускается вручную при наличии exe и модели).

## 8. Ручной чек-лист перевода

- [ ] `Ctrl+Alt+E` в Блокноте, Telegram, браузере → английский текст, он же в буфере обмена.
- [ ] Обычные клавиши при выключенной галочке → русский текст.
- [ ] Галочка «Переводить всегда» в трее → обычные клавиши дают английский; снятие галочки возвращает русский.
- [ ] Фраза с английскими терминами («открой файл config в VS Code») → термины сохранены.
- [ ] Длинная фраза 30+ с → переведена целиком.
- [ ] Тишина с клавишей перевода → ничего не вставлено (никаких «Thank you for watching»).
- [ ] Engine `llm`: при выходе из VoicePaste `llama-server.exe` пропадает из диспетчера задач; при аварийном завершении — тоже.
- [ ] Engine `llm`, сервер убит вручную → следующая диктовка работает или вставляет оригинал со звуком ошибки; приложение живо.
- [ ] Смена движка/модели в настройках применяется без перезапуска.
- [ ] Простой: CPU ~0 %, `llama-server` не грузит GPU, пока нет запросов.
