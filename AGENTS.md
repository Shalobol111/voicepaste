## 1. Что мы строим

**VoicePaste** — локальное (без облака) Windows-приложение для голосового ввода текста.

Сценарий пользователя:
1. Пользователь стоит курсором в любом поле ввода (браузер, мессенджер, IDE, Word, Блокнот).
2. Нажимает горячую клавишу → начинается запись с микрофона, появляется индикатор «● Запись».
3. Говорит (русский, английский или смесь).
4. Завершает запись (повторное нажатие или отпускание клавиши — зависит от режима).
5. Речь распознаётся локально моделью Whisper на GPU.
6. Текст **копируется в буфер обмена** и **вставляется в активное поле ввода**.

### Обязательные требования
- Полностью офлайн. Сеть используется только для однократного скачивания модели (по явной команде пользователя).
- Языки: русский + английский, включая смешанную речь в одной фразе.
- Ускорение: NVIDIA GPU через CUDA. Если CUDA недоступна — работаем на CPU (медленнее, но работаем) и пишем предупреждение в лог/трей.
- Две горячие клавиши, **активные одновременно** (переключать режим не нужно; пустая строка отключает одну из них; одно и то же сочетание на обе нельзя):
  - **toggle** (`hotkey.toggle`) — нажал → запись, нажал ещё раз → стоп и распознавание;
  - **push-to-talk** (`hotkey.push_to_talk`) — держишь → запись, отпустил → стоп и распознавание.
  Запись останавливает только та клавиша, которой её начали; вторая в это время игнорируется.
- Интерфейс: иконка в трее + окно настроек + маленький оверлей-индикатор записи.
- Целевая ОС: **Windows 10/11 x64**. Кроссплатформенность не нужна, но платформенный код изолируй в отдельных модулях.

### Не цели (не делать без отдельной просьбы)
- Стриминговое распознавание «на лету» во время речи.
- Голосовые команды, редактирование текста голосом.
- Облачные API, телеметрия, автообновление.
- Поддержка macOS/Linux.

## 2. Стек (зафиксирован, не менять без согласования)

Язык: **Rust** (stable, edition 2021, toolchain `x86_64-pc-windows-msvc`).

| Задача | Crate | Заметки |
|---|---|---|
| Распознавание речи | `whisper-rs` (feature `cuda`) | Биндинги к whisper.cpp. Модель GGML. |
| Захват звука | `cpal` | WASAPI. |
| Ресемплинг в 16 kHz mono | `rubato` | Whisper принимает только 16 kHz mono f32. |

| Иконка в трее | `tray-icon` (+ `muda` для меню) | |
| Цикл событий главного потока | `winit` | `EventLoop<UserEvent>` + `EventLoopProxy` для событий из других потоков. |
| Окно настроек | `eframe` / `egui` | Запускается **отдельным процессом** (см. 3.3). |
| Буфер обмена | `arboard` | |
| Эмуляция Ctrl+V, оверлей, WinAPI | `windows` (crate от Microsoft) | `SendInput`, `GetForegroundWindow`, создание окна оверлея. |
| Конфиг | `serde` + `toml` | |
| Слежение за конфигом | `notify` | Перезагрузка настроек без перезапуска. |
| Пути | `directories` | `%APPDATA%\VoicePaste\`. |
| Каналы между потоками | `crossbeam-channel` | |
| Ошибки | `anyhow` (в приложении), `thiserror` (типизированные ошибки модулей) | |
| Логи | `tracing` + `tracing-subscriber` + `tracing-appender` | Лог в файл с ротацией по дням. |

| Скачивание модели | `ureq` | Только по кнопке в настройках. |

**Версии крейтов:** не полагайся на память. Добавляй зависимости через `cargo add <crate>` (берётся актуальная версия), затем **сверяй API с docs.rs для конкретной установленной версии**. Особенно это касается `whisper-rs`, `global-hotkey`, `tray-icon`, `winit`, `eframe` — их API часто меняется между минорными версиями. Если пример из памяти не компилируется — открой исходники крейта в `~/.cargo/registry/src/` и посмотри реальную сигнатуру.

### Модель
- По умолчанию: `ggml-large-v3-turbo-q5_0.bin` (~0.5–0.6 ГБ, хорошее качество для ru/en, быстро на GPU).
- Альтернативы в настройках: `ggml-large-v3-turbo.bin` (полная, точнее), `ggml-medium-q5_0.bin`, `ggml-small-q5_1.bin` (для CPU; файла `small-q5_0` на HuggingFace нет).
- Источник: `https://huggingface.co/ggerganov/whisper.cpp/resolve/main/<file>`.
- Хранение: `%APPDATA%\VoicePaste\models\`.

## 3. Архитектура

### 3.1 Потоки

```
┌─────────────────────────── Main thread (winit EventLoop) ───────────────────────────┐
│  AppState (state machine) · tray-icon · global-hotkey · overlay (Win32) · config    │
│  Получает UserEvent через EventLoopProxy                                            │
└───────┬───────────────────────────────┬─────────────────────────────┬───────────────┘
        │ start/stop                    │ TranscribeJob(Vec<f32>)     │ ConfigReloaded
        ▼                               ▼                             │
┌──────────────────┐          ┌──────────────────────┐        ┌───────┴────────┐
│ Audio (cpal)     │          │ STT worker thread    │        │ notify watcher │
│ callback → буфер │          │ владеет WhisperCtx   │        └────────────────┘
└──────────────────┘          │ → UserEvent::Text    │
                              └──────────────────────┘
```

- **Главный поток** — единственное место, где живут трей, хоткеи и оверлей (они требуют Win32 message loop на том же потоке, где созданы). Никакой тяжёлой работы в главном потоке.
- **Аудио**: `cpal::Stream` создаётся при старте записи и уничтожается при остановке (чтобы индикатор микрофона Windows не горел постоянно). В callback — только копирование сэмплов в заранее выделенный буфер / `ringbuf`, без аллокаций и блокирующих локов надолго. Сведение каналов в mono — в callback или после; ресемплинг — после остановки, в STT-потоке.
- **STT worker** — отдельный долгоживущий поток. Модель загружается **один раз при старте приложения** и держится в памяти. После загрузки — прогрев (распознать 1 сек тишины), чтобы первая реальная диктовка была быстрой. Принимает задания через канал, отдаёт результат через `EventLoopProxy`.

### 3.2 State machine (`app.rs`)

```
          hotkey start                    hotkey stop
  Idle ───────────────► Recording ───────────────────► Transcribing
   ▲                       │ (запись < min_duration                │
   │                       │  или ошибка) → Idle                   │ текст готов
   └───────────────────────┴───────────────────────────────────────┘
                              вставка в поле + буфер → Idle
```

Плюс состояние `Loading` (модель грузится при старте) и `Error(String)`.

Правила:
- Сборка по умолчанию — консольная (feature `console`, логи на экране); трей-only GUI-exe: `cargo build --release --no-default-features`.
- Отладка: `--dump-audio <dir>` (WAV + статистика), `--transcribe-file <wav> [lang] [beam] [prompt]`, `--device <часть имени>`, `--model <путь>`.
- В `Transcribing` нажатие хоткея **игнорируется** (лог + короткий «отказ»-звук, если звуки включены).
- В `Loading` хоткей игнорируется, в трее tooltip «Загрузка модели…».
- В режиме push-to-talk автоповтор клавиши шлёт повторные `Pressed` — игнорировать `Pressed`, если уже `Recording`.
- Максимальная длительность записи (`max_record_seconds`, по умолчанию 300) — по достижении автоматически стоп и распознавание.
- Запись короче `min_record_ms` (по умолчанию 300) — отбрасывается без распознавания.
- Логика переходов — **чистая функция** `fn transition(state, event) -> (state, Vec<Effect>)`, без побочных эффектов внутри; эффекты (запустить запись, показать оверлей, вставить текст) исполняет отдельный код. Это нужно для юнит-тестов.

### 3.3 Окно настроек — отдельный процесс

`voicepaste.exe --settings` открывает окно `eframe`. Основной процесс по пункту трея «Настройки…» запускает `std::env::current_exe()` с этим флагом.

Почему так: `eframe` хочет владеть главным event loop'ом и плохо уживается со скрытым окном + треем в одном процессе. Отдельный процесс полностью убирает эту проблему.

- Окно настроек только читает/пишет `config.toml` (атомарно: запись во временный файл + rename).
- Основной процесс видит изменение через `notify`, перечитывает конфиг, перерегистрирует хоткеи, при смене модели/устройства — перезагружает модель в STT-потоке.
- Защита от двух окон настроек — именованный mutex `Local\VoicePaste.Settings`.
- Защита от двух экземпляров основного приложения — именованный mutex `Local\VoicePaste.Main`; если уже запущено — показать сообщение и выйти.

### 3.4 Вставка текста (`output.rs`) — самое хрупкое место

Алгоритм после получения текста:
1. Постобработка текста (раздел 5).
2. Если текст пустой — ничего не делать (не трогать буфер обмена), короткий звук «пусто».
3. Записать текст в буфер обмена (`arboard`). Буфер бывает занят другим процессом → до 5 попыток с паузой 20 мс.
4. **Дождаться отпускания модификаторов**: пользователь может ещё держать Ctrl/Alt/Shift/Win от хоткея. Опрашивать `GetAsyncKeyState` для `VK_CONTROL`, `VK_MENU`, `VK_SHIFT`, `VK_LWIN`, `VK_RWIN` каждые 10 мс, таймаут 1 сек. Без этого Ctrl+Alt+V вместо Ctrl+V.
5. Пауза `paste_delay_ms` (по умолчанию 40).
6. Отправить вставку через `SendInput` одним массивом событий. Метод задаётся `paste_method`:
   - `ctrl_v` (по умолчанию) — VK_CONTROL down, `V` down, `V` up, VK_CONTROL up. Используй виртуальные коды, а не символы — работает при любой раскладке.
   - `shift_insert` — для терминалов, где Ctrl+V не работает.
   - `type` — посимвольный ввод `KEYEVENTF_UNICODE` (для полей, блокирующих вставку). Медленнее.
7. Буфер обмена **не восстанавливать** — пользователь хочет, чтобы текст остался там.
8. Если активное окно — наше собственное (окно настроек) — только буфер, без вставки.

Известные ограничения (отразить в README и логах, не пытаться «обойти» хаками):
- Windows UIPI: в окна, запущенные от администратора, вставка из неповышенного процесса не работает. Текст при этом остаётся в буфере — пишем в лог `warn`.
- Оверлей и звуки **не должны** забирать фокус у активного окна — иначе вставка уйдёт не туда.

### 3.5 Оверлей (`overlay.rs`)

Маленькое окно на чистом Win32 (crate `windows`), без winit:
- Стили: `WS_POPUP`, ex-стили `WS_EX_TOPMOST | WS_EX_NOACTIVATE | WS_EX_TOOLWINDOW | WS_EX_LAYERED | WS_EX_TRANSPARENT` (не в таскбаре, не активируется, клики проходят насквозь).
- Показ только через `ShowWindow(hwnd, SW_SHOWNOACTIVATE)`; никогда не вызывать `SetForegroundWindow`/`SetFocus`.
- Положение: по центру внизу монитора, на котором находится активное окно (`MonitorFromWindow(GetForegroundWindow())`), отступ 80 px от нижнего края рабочей области.
- Состояния: «● Запись 0:07» (красная точка, таймер обновляется раз в секунду), «⏳ Распознаю…», скрыт.
- Рисование: GDI, полупрозрачный тёмный фон со скруглением, белый текст, шрифт Segoe UI. Отключается опцией `show_overlay`.

### 3.6 Трей (`tray.rs`)

- Иконки рисуются в коде (`tray.rs`, 32×32 RGBA, без файлов ресурсов): серая — idle, красная — запись, жёлтая — распознавание/загрузка, оранжевая с «!» — ошибка.
- Tooltip: «VoicePaste — готово (Ctrl+Alt+Space)», «Запись…», «Распознаю…», «Загрузка модели…», «Ошибка: …».
- Меню:
  - `Настройки…` (запускает `--settings`)
  - `Открыть config.toml`, `Открыть папку моделей`
  - `Открыть папку логов`
  - разделитель
  - `Выход`

## 4. Распознавание (`stt.rs`)

- Тип `SttEngine` скрывает `whisper-rs`. Публичный API:
  ```rust
  pub struct SttEngine { /* ctx, state */ }
  impl SttEngine {
      pub fn load(cfg: &SttConfig) -> anyhow::Result<Self>;   // грузит модель, use_gpu по конфигу
      pub fn transcribe(&mut self, pcm_16k_mono: &[f32]) -> anyhow::Result<String>;
      pub fn backend(&self) -> Backend;                         // Cuda | Cpu — для трея/логов
  }
  ```
- Загрузка: сначала с `use_gpu = true`; если не удалось (нет CUDA/драйвера) — повторить на CPU, залогировать `warn`, показать в трее.
- Параметры по умолчанию:
  - стратегия: `BeamSearch { beam_size: 5 }` (настройка `beam_size`; 1 = greedy, быстрее);
  - `language`: из конфига — `"auto"` (по умолчанию), `"ru"`, `"en"`. Для смешанной ru/en речи `"ru"` часто работает лучше, чем `auto` на коротких фразах — пользователь выбирает в настройках;
  - `translate = false`, `no_context = true`, `suppress_blank = true`, `temperature = 0.0`;
  - `n_threads`: `min(8, num_cpus)`;
  - отключить все `print_*` в stdout;
  - `initial_prompt`: из конфига. Значение по умолчанию задаёт пунктуацию и стиль: `"Привет. Это обычный текст с правильной пунктуацией, запятыми и точками. Hello, this is English text."`. Пользователь может дописать туда свои термины (имена, жаргон).
- Склейка сегментов: конкатенация текста всех сегментов через пробел, затем постобработка.
- Перед распознаванием: обрезать тишину в начале и конце по RMS-энергии (окно 30 мс) с **адаптивным порогом** `max(0.0015, 3×шум, 5% от пика)` и запасом 300 мс. Фиксированный порог 0.01 отрезал тихие окончания фраз на тихих микрофонах (пик речи ~0.03). «Речь есть», если пик окна ≥ 0.004. Конфиг-параметра для порога нет. Если после обрезки осталось < 300 мс — считать, что речи не было, вернуть пустую строку **без вызова Whisper** (главная защита от галлюцинаций).

## 5. Постобработка текста (`postprocess.rs`)

Чистые функции, покрыть тестами:
1. Удалить служебные маркеры: `[BLANK_AUDIO]`, `[музыка]`, `(музыка)`, `[Music]`, `*...*` и т.п. — любые фрагменты в `[...]`/`(...)`, состоящие из списка известных маркеров.
2. **Фильтр галлюцинаций**: если весь результат (после trim, без учёта регистра и пунктуации) совпадает с одной из известных фраз — вернуть пустую строку. Список вынести в константу, минимум:
   - «Продолжение следует…», «Субтитры сделал DimaTorzok», «Субтитры создавал DimaTorzok», «Редактор субтитров А.Синецкая», «Спасибо за просмотр», «Thank you for watching», «Thanks for watching!», «Подписывайтесь на канал».
3. Схлопнуть повторяющиеся пробелы, убрать пробелы перед `.,!?:;`, trim.
4. Опция `trailing_space` (по умолчанию `true`) — добавить пробел в конце, чтобы следующая диктовка не слипалась.
5. Опция `strip_final_period` (по умолчанию `false`) — убрать точку в конце (удобно для чатов).

## 6. Конфигурация

Файл: `%APPDATA%\VoicePaste\config.toml`. Если нет — создаётся со значениями по умолчанию. Неизвестные поля игнорируются, отсутствующие — берутся по умолчанию (`#[serde(default)]`). Битый файл → лог `error`, работаем на дефолтах, файл **не перезаписываем**.

```toml
[hotkey]
# Обе клавиши активны одновременно, "" = отключена. Ключа `mode` больше нет (старый файл читается, ключ игнорируется).
toggle = "Ctrl+Alt+D"         # Ctrl+Alt+Space занят приложением Claude на машине пользователя
push_to_talk = "Ctrl+Alt+S"

[audio]
input_device = ""             # "" = устройство по умолчанию; иначе имя из cpal
max_record_seconds = 300
min_record_ms = 300

[stt]
model = "ggml-large-v3-turbo-q5_0.bin"
use_gpu = true
language = "auto"             # "auto" | "ru" | "en"
beam_size = 5
initial_prompt = "Привет. Это обычный текст с правильной пунктуацией, запятыми и точками. Hello, this is English text."

[output]
paste = true                  # false = только буфер обмена
paste_method = "ctrl_v"       # "ctrl_v" | "shift_insert" | "type"
paste_delay_ms = 40
trailing_space = true         # игнорируется, если включён press_enter
strip_final_period = false
lowercase_first = false       # начинать текст с маленькой буквы (аббревиатуры и "I" не трогаются)
press_enter = false           # нажать Enter после вставки (отправка сообщения в чате)

[ui]
show_overlay = true
sounds = true
sound_volume = 70             # 0..100 %
autostart = false
```

Если устройство `input_device` не найдено — fallback на устройство по умолчанию + `warn`.

## 7. Окно настроек (`settings_ui.rs`, `eframe`)

Вкладки или секции:
- Стиль окна: тёмный «ретро» (безрамочное окно, тонкие рамки, зелёные заголовки на линии рамки, журнал внизу — хвост реального лога). Сохранение пишет `config::render()` (с комментариями), а не голый serde.
- **Горячие клавиши**: два поля (переключатель и удержание), у каждого поле захвата сочетания («Нажмите сочетание…» → считывает модификаторы + клавишу из событий egui). Валидация: сочетание должно содержать хотя бы один модификатор или быть F-клавишей. Проверка конфликта: попробовать зарегистрировать — если ОС отказала, показать «Сочетание занято другим приложением».
- **Микрофон**: выпадающий список устройств `cpal`, кнопка «Проверить» — индикатор уровня громкости в реальном времени.
- **Распознавание**: выбор модели из файлов в папке `models` + список известных моделей с кнопкой «Скачать» (прогресс-бар, скачивание в `*.part` и rename по завершении; проверка размера). Язык, beam size, GPU вкл/выкл, поле initial prompt (многострочное).
- **Вставка**: paste вкл/выкл, метод, задержка, trailing space, strip final period.
- **Интерфейс**: оверлей, звуки, автозапуск с Windows (`HKCU\Software\Microsoft\Windows\CurrentVersion\Run`, значение `VoicePaste` = путь к exe в кавычках).
- Кнопки «Сохранить» и «Отмена». Сохранение — атомарная запись `config.toml`.
- Весь UI на русском.

## 8. Структура проекта

Один бинарный crate (без workspace), модули:

```
VoicePaste/
├─ AGENTS.md
├─ README.md               # сборка, установка CUDA, где модели, ограничения
├─ Cargo.toml
├─ build.rs                # иконка exe и манифест (winres / embed-resource), DPI-aware манифест
├─ assets/
│  ├─ icons/ idle.ico recording.ico busy.ico error.ico app.ico
│  └─ sounds/ start.wav stop.wav error.wav
└─ src/
   ├─ main.rs              # #![windows_subsystem = "windows"] в release; разбор аргументов; single-instance; запуск app или settings
   ├─ app.rs               # EventLoop, AppState, transition(), исполнение эффектов
   ├─ config.rs            # структуры, default, load/save (atomic), watcher
   ├─ paths.rs             # %APPDATA%\VoicePaste\{config.toml, models\, logs\}
   ├─ audio.rs             # список устройств, Recorder::start/stop -> Vec<f32>, downmix, resample 16k
   ├─ stt.rs               # SttEngine, worker thread, trim silence
   ├─ postprocess.rs       # очистка текста, фильтр галлюцинаций
   ├─ output.rs            # clipboard + SendInput, ожидание отпускания модификаторов
   ├─ hotkey.rs            # парсинг строки сочетания, регистрация/перерегистрация
   ├─ tray.rs              # иконки, меню, tooltip
   ├─ overlay.rs           # Win32 no-activate окно
   ├─ sound.rs             # проигрывание встроенных WAV (асинхронно, не блокировать главный поток)
   ├─ platform.rs          # mutex single-instance, MessageBox для фатальных ошибок
   ├─ wav.rs               # мини-WAV reader/writer для --dump-audio и --transcribe-file
   ├─ autostart.rs         # реестр Run
   ├─ model_download.rs    # ureq + прогресс
   └─ settings_ui.rs       # eframe-приложение
```

Весь `unsafe` и WinAPI — только в `output.rs`, `overlay.rs`, `autostart.rs`, `main.rs` (mutex). Каждый `unsafe`-блок — с комментарием `// SAFETY: ...`.

## 9. План работы по этапам

Каждый этап заканчивается **компилирующимся, работающим** состоянием. После этапа: `cargo fmt`, `cargo clippy --all-targets -- -D warnings`, `cargo test`, затем короткий отчёт: что сделано, как проверить вручную, что не получилось. Не начинай следующий этап, пока текущий не проверен.

### Этап 0. Окружение и «скелет»
- Проверь наличие: `rustc`, `cargo`, MSVC Build Tools, CMake, LLVM/Clang (`LIBCLANG_PATH` для bindgen), CUDA Toolkit (`nvcc --version`, `CUDA_PATH`). Если чего-то нет — **остановись и сообщи пользователю**, что установить, не пытайся ставить сам.
- `cargo init`, зависимости этапа 1, `.gitignore` (target/, *.bin модели).
- Критерий: `cargo build --release` проходит с `whisper-rs` + feature `cuda`. Это самый рискованный шаг сборки — сделай его первым.

### Этап 1. Доказательство работоспособности (консоль)
- `voicepaste --test-mic 5`: записать 5 сек с микрофона по умолчанию → ресемплинг → распознать → напечатать текст, время распознавания и backend (CUDA/CPU).
- Модель берётся по пути из аргумента или из `%APPDATA%\VoicePaste\models\`.
- Критерий: русская и английская фраза распознаются корректно; в логе видно, что используется CUDA; распознавание 5 сек речи на GPU < 1 сек.

### Этап 2. Хоткей → запись → буфер → вставка (toggle, без трея)
- winit event loop, global-hotkey, state machine (`transition` + тесты), STT worker, `output.rs`.
- Конфиг пока захардкожен значениями по умолчанию.
- Критерий: в Блокноте Ctrl+Alt+Space → говорю → Ctrl+Alt+Space → текст появился в поле и лежит в буфере обмена. Повторное нажатие во время распознавания игнорируется.

### Этап 3. Трей, конфиг, логи, single-instance
- `tray.rs`, `config.rs` (+ watcher), `paths.rs`, логирование в файл, `windows_subsystem = "windows"` в release, именованный mutex.
- Критерий: приложение запускается без консоли, видно в трее, иконка меняется по состояниям, правка `config.toml` вручную применяется без перезапуска (в т.ч. смена хоткея).

### Этап 4. Push-to-talk
- Обработка `Released`, защита от автоповтора, переключение режима из меню трея.
- Критерий: держу сочетание — пишет, отпустил — вставилось; модификаторы не «залипают», вставка не превращается в Ctrl+Alt+V.

### Этап 5. Оверлей и звуки
- `overlay.rs`, `sound.rs`.
- Критерий: оверлей виден поверх всех окон, **фокус не теряется** (проверить: во время записи курсор в поле браузера продолжает мигать, вставка уходит туда же).

### Этап 6. Окно настроек
- `--settings`, `settings_ui.rs`, атомарное сохранение, mutex окна, тест микрофона, захват хоткея.
- Критерий: все поля раздела 6 редактируются из UI и применяются в работающем приложении без перезапуска.

### Этап 7. Полировка

**Статус (07.10.2026):** сделано — фильтр галлюцинаций и маркеры шума, автозапуск (реестр), скачивание моделей (`model_download.rs`, кнопки в настройках), иконка и манифест (`build.rs`, `assets/`), README, фичи Cargo `cuda`/`console`, скрипты `scripts/build-release.ps1` и `scripts/package.ps1`, версия 1.0.0. Решение пользователя: релиз NVIDIA собирается **только под RTX 40 (sm_89)**, плюс отдельная CPU-версия. Осталось: ручной чек-лист (раздел 11) на готовых сборках.
- Скачивание моделей, автозапуск, фильтр галлюцинаций, обрезка тишины, CPU-fallback, иконка exe и манифест, README.
- Сборка релиза: в README описать, какие CUDA DLL (`cudart64_*.dll`, `cublas64_*.dll`, `cublasLt64_*.dll`) нужно положить рядом с exe для запуска на машине без CUDA Toolkit.
- Критерий: ручной чек-лист (раздел 11) пройден.

## 10. Правила кода

- `cargo fmt` и `cargo clippy -- -D warnings` — без исключений.
- Никаких `unwrap()`/`expect()` в не-тестовом коде, кроме случаев, когда инвариант гарантирован — тогда `expect("почему это невозможно")`.
- Ошибки: `thiserror` внутри модулей, `anyhow` + `.context("...")` на границах. Ошибка в любом месте не должна ронять приложение — переход в `Error`/`Idle`, лог, иконка ошибки в трее.
- Паника в потоке STT/аудио не должна убивать процесс незаметно: `catch_unwind` или проверка `JoinHandle`, перезапуск воркера, лог.
- Никакой блокирующей работы в главном потоке (загрузка модели, распознавание, скачивание, sleep > 50 мс). Ожидание отпускания модификаторов и вставку делай в отдельном коротком потоке.
- Комментарии в коде — на английском; строки UI — на русском; сообщения коммитов — на английском.
- Не добавляй зависимости сверх таблицы раздела 2 без обоснования в отчёте.
- Не логируй распознанный текст на уровне выше `debug` (приватность). Аудио на диск не писать (кроме явного debug-флага `--dump-audio`).
- Пиши код маленькими модулями с узким публичным API, как описано в разделе 8.

### Тесты (`cargo test`)
- `postprocess`: маркеры, галлюцинации, пробелы, опции.
- `app::transition`: все переходы, включая игнор хоткея в `Transcribing`, автоповтор в PTT, `min_record_ms`, `max_record_seconds`.
- `config`: дефолты, частичный файл, битый файл.
- `hotkey`: парсинг строк `"Ctrl+Alt+Space"`, `"F9"`, `"Ctrl+Shift+D"`, отказ на некорректных.
- `audio`: downmix стерео→моно, ресемплинг 48k→16k (длина результата, отсутствие NaN), обрезка тишины.

## 11. Ручной чек-лист перед завершением

- [ ] Блокнот, Chrome (адресная строка и textarea), VS Code, Telegram Desktop, Word, Windows Terminal (с `shift_insert`).
- [ ] Русская фраза, английская фраза, смешанная («открой файл config в VS Code»).
- [ ] Нажать хоткей и молчать 3 сек → ничего не вставлено, никаких «Продолжение следует…».
- [ ] Очень короткое нажатие (< 300 мс) → игнор.
- [ ] Запись 2+ минуты → корректно распознаётся целиком.
- [ ] Раскладка клавиатуры английская и русская — вставка работает в обеих.
- [ ] Окно, запущенное от администратора → текст в буфере, в логе warn.
- [ ] Отключить микрофон во время работы → ошибка в трее, приложение живо, после подключения работает.
- [ ] Смена хоткея/модели/режима в настройках применяется без перезапуска.
- [ ] Второй запуск exe → сообщение «уже запущено».
- [ ] Без CUDA (`use_gpu = false`) → работает на CPU.
- [ ] Потребление в простое: CPU ~0%, микрофон не занят (индикатор микрофона Windows не горит).

## 12. Когда спрашивать пользователя

Остановись и спроси, если:
- не хватает инструментов сборки (CUDA, CMake, LLVM) или сборка `whisper-rs` с CUDA не проходит после 2–3 осмысленных попыток;
- требование из этого файла невозможно выполнить выбранным крейтом (например, нужна клавиша-одиночка без модификатора вроде одного Right Ctrl — это требует low-level keyboard hook `WH_KEYBOARD_LL` вместо `global-hotkey`; не переходи на него без согласования);
- хочешь изменить стек, архитектуру потоков или добавить заметную зависимость.

Не спрашивай о мелочах, решаемых здравым смыслом, — прими решение и укажи его в отчёте об этапе.
